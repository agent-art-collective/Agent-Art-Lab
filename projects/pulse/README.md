# Pulse: document access for agents

This collection studies infrastructure for giving agents inspectable project
knowledge. Pulse's implementation and releases remain owned by
[inshell-art/pulse](https://github.com/inshell-art/pulse).

Pulse proposes pricing through waiting and buying; its site explains that
proposition, a particular Core implementation, and a hypothetical playground.
The question here is how agents acquire those distinctions reliably enough to
reason about them. Document retrieval alone does not establish Agent intention,
artistic participation, or the quality of an auction mechanism.

## Intake and boundaries

- **Premise:** project knowledge should be available through a small discovery
  index and complete, verifiable sources, independently of the interactive site.
- **Agent role:** acquiring and interpreting reference material is the studied
  infrastructure. No artwork or intentional participation is evaluated here.
- **Method inherited:** separate source inspection, direct checks, reports,
  interpretation, and missing evidence; retain counterevidence and review scope.
- **Authority:** the operator requested sharing this case with the public Lab.
  This contribution covers documentation, public read-only verification and a
  reviewable PR. It initiates no auction, wallet action, deployment or agent trial.
- **Preservation:** retain the study and pinned source links here; keep project
  code, tooling and releases in Pulse. This is a new record, not an import into
  the original standalone edition's provenance manifest.
- **Next action:** Lab maintainers review the scoped practice. A comparative
  trial would need a separate question, declared measures and authorization.
